# 交接文件

這份文件整理了第一個工作階段（2026 年 11 月 25～27 日）的討論與決策。新的工作階段請先讀這份，再讀 `README.md`。

## 一、遊戲的出發點（使用者的原始構想）

- 反映台灣的交通亂象，特別是行人和機車騎士受到的困擾：路邊停車、違規停車，以及不合理的交通規則，例如禁行機車道、兩段式左轉、機車過橋要繞專用道。
- 玩法結合「倉庫番（推箱子）」和「跑酷」：本質是益智遊戲，但要有刺激感；主角是行人或機車騎士，所以節奏不能像一般跑酷那麼快。
- 風格要可愛，最初的想像是黏土或積木。

## 三、決策紀錄

### 玩法

1. **回合制**：玩家走一步，所有車子也動一步，也可以原地「等一下」。刺激感來自預判車流，而不是反應速度。
2. **車比人快**：部分車道一回合走兩格，避免玩家跟著車流走在馬路上偷懶。
3. **危險預告**：紅、橘、黃框分別是一、二、三步後車子會開到的格子（假設玩家原地不動）。
   - 原因：最早的第一關只能靠背答案過關，使用者質疑「沒有人能發現要這樣破」。只預告一步也不夠，因為關卡需要提前規劃好幾步。
   - 預告必須跟實際撞車完全一致，`npm run check` 會驗證這一點。
4. **曾加過「來車倒數」**：地圖邊緣的小標籤，顯示幾步後有車開進來。使用者覺得畫面太亂，已拿掉。
5. **機車推不動**：使用者認為「推別人的機車」不符合現實。違停機車和汽車都是固定障礙；推得動的是店家擺出來的招牌、盆栽、垃圾桶、施工三角錐，以及自己的嬰兒車。
6. **嬰兒車關卡**：使用者希望「某些關卡」是推嬰兒車或輪椅。目前第 3 關是推嬰兒車：嬰兒車要推到終點，只能推不能拉，過不了台階，在馬路上被撞也算失敗。

### 關卡

- **第一關改過兩次**：
  - 原版幾乎只能靠背答案，而且解法踩到一個 bug（見下方）。
  - 第二版在兩條車道間換來換去就能過，完全不用推東西，推箱子的玩法失去意義。
  - 現在的版本只有一條迎面車道，機車三台一組沒有空隙可以躲，必須把招牌和垃圾桶推回店門口，騎樓才會空出躲車的位置。已驗證：不推東西就過不了。
- **原版第一關保留為第 6 關「地獄模式」**，是使用者要求留下來的。
- 每一關的最少步數由建置時的解題程式算出，三星門檻是最少步數加 2。

### 修過的 bug

1. 站在地圖邊緣、車子會出現的那一格，原本會無敵，因為車子不會生成。現在改成車子從地圖外開進來時會撞到人。
2. 一回合走兩格的車開出地圖時，最後經過的格子原本不會被標成危險。已修正。
3. 檢查工具原本沒有考慮「被撞的是嬰兒車」，導致嬰兒車關卡誤報不一致。已修正，遊戲本身沒有問題。

### 畫面

- 台階原本畫成幾條橫向色帶，使用者覺得像畫面壞掉，已改成兩側有踏階的高台並加上「台階」標籤。
- 使用者認為 2D 原型和早期三種 2D 風格（等角積木、交通標誌扁平、剪紙貼紙）「都超陽春」，要求「一看就想讓人花錢購買、至少 Candy Crush 的水準，但不要照抄」。
- 因此改用 three.js 做 3D 渲染，做了 3D 樣張和五個美術方向（見下一節）。

## 四、美術方向（尚未定案）

| 方向 | 特色 | 備註 |
|---|---|---|
| 01 糖果街角 | 亮面糖果玩具、果凍按鈕 | 最主流，但容易撞臉 |
| 02 夜市霓虹 | 夜景、霓虹招牌、燈籠串 | 截圖最吸睛，暗色畫面和效能是風險 |
| 03 黏土定格 | 霧面黏土、移軸景深、紙膠帶標題 | 最接近原始構想 |
| 04 漫畫爆炸 | 粗描邊、原色、「叭！！」狀聲詞 | 喜感最強，規則最好認 |
| 05 晨光散步 | 粉紫低多邊形、明體直排 | 最療癒，但危險感最弱 |

**目前的建議**：以 03 黏土定格為主，02 夜市霓虹做夜間關卡或商店宣傳圖。**使用者還沒有選定**，下一個工作階段應先問使用者的決定。

已知弱點：所有方向的角色都還是簡單幾何造型，跟場景的完成度不在同一個等級。

## 五、建議的下一步

1. 請使用者選定美術方向（或混搭）。
2. 角色設計：主角的臉、表情和動作，以及嬰兒車、違停機車和汽車的造型。
3. 把一關（建議第 3 關）做成可以玩的 3D 版本，並把手感做到位：推動時的回彈、撞車和過關的演出、音效。
4. 在手機上確認效能，夜市霓虹尤其要注意。
5. 更多關卡題材（使用者還沒選）：路邊停車開門殺、人行道上的變電箱和攤販、公車站牌被違停擋住、大車內輪差、騎樓的斜坡和水溝蓋。

## 六、跟使用者合作的注意事項

- 使用繁體中文溝通。
- 使用者重視成品品質，會直接指出「陽春」「太亂」「不合理」。交出去之前先自己截圖看過。
- 規則要合乎現實，關卡的解法也要讓玩家看得出來，不能只靠背答案。
- 每次改關卡都要用解題程式和檢查工具驗證，並誠實回報結果。
